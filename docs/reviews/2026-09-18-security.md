# Security and privacy review — 2026-09-18 (pre-launch, Phase 9)

Scope: full codebase at commit after content sprint B (auth, sandbox, payments, RLS, headers, secrets, PII, admin, analytics). Method: manual read of `src/lib/**`, migrations and hooks; `npm audit`; pgTAP suites 0001–0008 reviewed (executed on PGlite smoke scripts, CI runs them on Docker); CSP/headers asserted by E2E 01. Severity: **Critical / High / Medium / Low / Info**.

## Findings

| #    | Sev    | Area         | Finding                                                                                                                                                                                                                                                                      | Status                                                                                                             |
| ---- | ------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| S-1  | Medium | Certificates | Public `/verificar/[code]` had no rate limit despite `limits.rateLimits.verification` existing; codes are 20 random chars (≈ 10^31) so enumeration is impractical, but scraping was unbounded.                                                                               | **Fixed** in this review: per-IP token bucket (`verificationRateLimited`, hashed IP, `consume_rate_limit`).        |
| S-2  | Medium | Deployment   | Dataset snapshots were git-ignored and not built during `next build`, so a Vercel deploy would have shipped without datasets (availability, not confidentiality).                                                                                                            | **Fixed** (sprint B): `prebuild` runs `datasets:build`.                                                            |
| S-3  | Low    | Admin        | `admin_find_user` returns the account email to admins; reads are not audit-logged (only mutations are).                                                                                                                                                                      | Open — acceptable for a 1–2 admin team; add read auditing if the admin roster grows (tracked in ROADMAP post-MVP). |
| S-4  | Low    | Analytics    | `track()` runs inside request handlers and awaits the insert; a Supabase outage adds latency to learner actions (never failure: errors are swallowed).                                                                                                                       | Open — move to `after()` (Next.js) post-launch.                                                                    |
| S-5  | Low    | CSP          | `style-src 'unsafe-inline'` is required by Next.js/Tailwind style injection. Scripts remain nonce + `strict-dynamic`.                                                                                                                                                        | Accepted, documented in SECURITY.md §5.                                                                            |
| S-6  | Info   | Payments     | Hotmart webhook verifies `hottok` with constant-time compare and re-fetches the purchase before granting (`HOTMART_SKIP_REFETCH` only for local/CI). Manual purchases require admin approval with audit. Unmatched events are quarantined and reconciled manually (Phase 8). | OK                                                                                                                 |
| S-7  | Info   | Sandbox      | Learner SQL never reaches the app DB: parser gate → denied functions → `learner` role in an isolated PGlite worker with hard kill. Window-frame normalization added in sprint B only blanks a closed grammar. Fuzz corpus 200+ inputs green.                                 | OK                                                                                                                 |
| S-8  | Info   | RLS          | 51 tables, all with RLS in their creating migration (`db:validate` asserts it); every `security definer` function pins `search_path` (asserted). Hints/solutions/expected results/`is_correct`/explanations are only readable through server code after unlock/submission.   | OK                                                                                                                 |
| S-9  | Info   | Secrets      | No secrets in source; `.env.example` placeholders only; `guard-bash`/`guard-write` hooks block secret-looking content and prod deploys; `npm audit`: 0 vulnerabilities. Owner passwords shared in chat were **not** stored and the owner was advised to rotate them.         | OK                                                                                                                 |
| S-10 | Info   | PII          | Profiles store minimal data; analytics events exclude SQL text, emails and free text; certificate verification exposes name/title/date/status only; data export/deletion requests exist (`requestDataAction`). Privacy policy (draft) mirrors these behaviors.               | OK                                                                                                                 |
